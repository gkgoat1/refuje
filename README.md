## Foundry

**Foundry is a blazing fast, portable and modular toolkit for Ethereum application development written in Rust.**

Foundry consists of:

- **Forge**: Ethereum testing framework (like Truffle, Hardhat and DappTools).
- **Cast**: Swiss army knife for interacting with EVM smart contracts, sending transactions and getting chain data.
- **Anvil**: Local Ethereum node, akin to Ganache, Hardhat Network.
- **Chisel**: Fast, utilitarian, and verbose solidity REPL.

## Usage

### Build

```shell
$ forge build
```

### Test

```shell
$ forge test
```

### Format

```shell
$ forge fmt
```

### Gas Snapshots

```shell
$ forge snapshot
```

### Anvil

```shell
$ anvil
```

### Deploy

```shell
$ forge script script/Counter.s.sol:CounterScript --rpc-url <your_rpc_url> --private-key <your_private_key>
```

### Cast

```shell
$ cast <subcommand>
```

### Help

```shell
$ forge --help
$ anvil --help
$ cast --help
```

## Refuje testing

Beyond `forge test` (unit + fuzz + invariant suites in `test/`), the contract
ships with symbolic and mutation testing:

- `src/RefujeSigner.sol` is a Solidity re-implementation of the Rust/TS
  signing clients (one-time keys, the depth-256 Merkle tree, target encoding,
  proof building) for Forge-based tests, scripts, and invariant handlers.
  `test/RefujeSigner.t.sol` pins it to fixed vectors generated by the
  TypeScript client.
- `test/RefujeSymbolic.t.sol` proves the withdrawal accounting for arbitrary
  amounts with halmos (the signature path has ~2^256 branches and stays
  fuzz-tested end-to-end instead):
  `npm run test:halmos`
- `test/mutants/` holds hand-written mutants of `src/Refuje.sol`;
  `npm run test:mutants` applies each one and expects the Forge suite to fail.
  Run `test/mutants/generate.sh` to regenerate the patches after editing the
  contract.

## Web console

The framework-free Vite frontend is in `web/`:

```sh
npm run dev:web
# or: npm run build:web
```

It discovers injected wallets through EIP-6963, lets you enter any Refuje
instance address (and an optional read RPC), shows the deployment's chain,
bytecode, and ETH balance, and exposes registration, ETH/ERC-20 deposits, and
raw pre-built withdrawal submission. It intentionally never asks for a private
key; generate withdrawal proofs with `src/index.ts` or `src/RefujeSigner.sol`
and paste the finalized calldata pieces into the raw-proof form. After
connecting a wallet, **Deploy Refuje instance** broadcasts a new deployment
from that account and selects the resulting address automatically. The web
build generates the creation bytecode from the Foundry artifact; browser
deployments do not handle verifier API keys, so use `scripts/deploy.sh` when code
verification is required.

## Deployment and verification

Copy `.env.example` to `.env`, set `RPC_URL`, `PRIVATE_KEY`, and an
`ETHERSCAN_API_KEY` (or choose another verifier), then run:

```sh
npm run deploy
```

`scripts/deploy.sh` broadcasts `script/Deploy.s.sol:DeployScript`, extracts the
created address and transaction from Foundry's broadcast artifact, and runs
`forge verify-contract` with the repository's via-IR and 1,000,000 optimizer-run
settings. For local Anvil deployments use `SKIP_VERIFY=1`.
